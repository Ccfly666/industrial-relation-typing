# Reproduction limits

- Original fetch_sources.py/audit.py were not recovered; newly authored tools were executed and verified against the actual snapshots.
- Historical role/Guard/GUplus decisions and upstream dependency fields are retained metadata, not independently rediscovered. Fixed CV and query blocks were regenerated from those declared inputs.
- L1 and L2 ran, and L3a completed one formal E scope. L3b/L3c are not claimed.
- The independent NumPy build uses OpenBLAS; the original feature build uses MKL. Fresh standardized Q63 differs by up to8.392333984375e-5, while the same-input MKL control reproduces Q63 exactly. Fresh RDF B7 differs by about1e-6 after scaling; refitted scoped LR probabilities differ by about5.1497e-5. These differences were retained after the initial strict intermediate tolerance check failed. Formal one-scope prediction differences are in actual_validation_receipt.json. No original result was replaced.
- A64 fit-specific projector and frozen name vectors are explicitly retained inputs in L3a. No new supervised projection fit is claimed. Frozen name batch ordering affects quantized encodings.
- Runtime numbers refer to declared component/query adapters and cache conditions, not universal deployment latency. Shared precomputation/maintenance cold start is not fully remeasured.
- Data, pretrained weights, per-row predictions and private acceptance inputs are not bundled. Authorized users must obtain them separately. The original54 replay manifest identifies supplied inputs by SHA.
